# 疑難排解與驗證

## 面板無法開啟或顯示連線中斷

1. 確認背景服務仍在執行。托盤存在時，從「開啟 Web UI」重新開啟。
2. 服務重啟會更換「本機 Web UI 存取憑證」，它只用來讓瀏覽器操作本地面板，與網域 API Key、API Secret、Bark 網址無關。若舊書籤或分頁失效，從托盤重新開啟即可；已儲存的密鑰與排程設定不會因此消失。
3. 無托盤模式請使用這次啟動時終端印出的完整網址，包含 `#` 後的本機 Web UI 存取憑證。
4. 若啟動時提示連接埠占用，可設定程序環境變數 `AUTOUPDOMAIN_PORT` 換成其他本地連接埠。

面板只監聽本機 `127.0.0.1`，不能直接從另一台電腦連入。不要分享帶有本機 Web UI 存取憑證的網址。

## `.env` 修改後仍使用舊設定

Web 儲存不會寫回 `.env`，而是將密鑰加密保存到使用者資料目錄的 `settings.json`。「留白保留」表示保留目前密鑰，重啟後仍可使用，不需要重新填寫。

常駐服務讀取專案根目錄 `.env`，修改後需重啟。Web 已儲存的設定優先於 `.env`，已有已儲存憑證時請在面板更新；留白會保留原值。`BARK_API=none` 僅作為設定預設值，不覆蓋 Web 已儲存的 Bark 開關。

`--ignore-env` 只略過檔案和程序中的憑證變數，不清除使用者資料目錄內的設定。若需要完全隔離的測試，應同時使用獨立的 `AUTOUPDOMAIN_DATA_DIR`，或使用 `npm run demo`。

## 托盤「立即檢查」後沒有通知

預設「重要結果」模式下，手動檢查會在每輪結束後發送一則結果摘要，即使沒有需要續期的網域或清單為空也會回覆。先前版本只通知續期或錯誤；更新程式後，請先退出舊服務再重新啟動。「所有結果」模式也會通知排程成功；「僅錯誤」模式則不通知手動成功。請確認通知時機已儲存。

若手動操作仍沒有通知，先確認系統通知已開啟並儲存，再查看控制台是否已完成檢查、是否正在等待 API，或是否出現通知管道失敗。關閉全部通知管道時只保留控制台紀錄。連續點擊或加入執行中的同一輪工作不會重複檢查或重複發送摘要。

要單獨驗證通知管道，請在 Web UI 勾選系統通知、儲存，再按「測試已儲存的通知設定」。若測試也未顯示，再依下方平台步驟排查。

## Windows 沒有看到通知

- 在面板確認「系統通知」已勾選並儲存，再按測試通知。
- 檢查 Windows 通知設定與勿擾模式。
- 首次通知會建立開始功能表內的 `AutoUPDomain Notifications.lnk`，用來識別通知來源。啟動應用仍使用 `npm start` 或專案的 VBS 啟動器。
- 若控制台顯示通知管道失敗，查看 `service.log` 與作業系統限制。

工具回報接受通知與使用者看見通知是不同結果。自動驗證只確認工具呼叫結果，實際通知顯示需人工確認。

## Linux 托盤、通知或憑證儲存失敗

Linux 桌面功能需要：

| 功能 | 需求 |
| --- | --- |
| 托盤 | 相容的 AppIndicator 桌面支援；部分 GNOME 桌面另需擴充 |
| 系統通知 | `notify-send` 與桌面通知服務 |
| 憑證加密 | `secret-tool`、libsecret 與已解鎖的登入金鑰圈 |
| 開啟瀏覽器 | `xdg-open` 及已設定的預設瀏覽器 |

Debian／Ubuntu 常見依賴安裝方式如下；套件名稱與相容性仍依發行版而定：

```sh
sudo apt install libnotify-bin libsecret-tools libayatana-appindicator3-1
```

托盤啟動失敗時 Web UI 服務仍可使用。可執行 `npm run start:headless`，從終端取得網址。純終端環境沒有桌面通知時可停用系統通知、改用 Bark。

即使使用無托盤模式，透過面板儲存密鑰仍需要金鑰圈；程式不會退回明文保存。服務資料中的加密憑證也不能直接複製到另一位使用者或另一個作業系統後繼續使用。

Linux 桌面通知、托盤與金鑰圈尚需在目標 Linux 圖形環境實機驗證；Windows 測試結果不代表 Linux 平台已通過。

## 執行控制台沒有新內容

確認控制台沒有按下「暫停更新」，日誌篩選為「全部日誌」，並確認面板仍連線。服務閒置時不會每秒新增日誌，只有實際工作或設定事件才會產生紀錄。

「暫停更新」只停止畫面；「暫停排程」才會停止後續自動檢查。兩者均不會強制中斷已開始的續期操作。

最近 200 筆保存在 `state.json`；控制台下載功能輸出目前緩存的日誌，清除日誌則會一併清空這份保存（需二次確認，無法復原）。`service.log` 是服務錯誤紀錄，不包含每一筆網域流程。

## 續期未確認

續期請求可能已在遠端生效，即使本地收到逾時。程式不會立即重送 POST，而會重新查詢到期時間；確認日期延長才標示成功。

請檢查控制台錯誤、憑證與供應商狀態。失敗後下一輪會於 1 小時後執行。避免同時在其他電腦或 CLI 執行同一組網域的續期；本地單實例鎖不涵蓋其他機器或單次 CLI。

## 驗證指令

```sh
npm test
node scripts/service-smoke.mjs
node scripts/native-smoke.mjs
```

- `npm test`：模擬 API、排程、設定優先序、本地端點、單實例及日誌遮蔽測試；Windows 另外驗證 DPAPI。
- `service-smoke.mjs`：使用 `output/service-restart` 隔離資料與 `--ignore-env`，驗證服務重啟後的加密設定還原。Linux 執行時仍需要可用金鑰圈。
- `native-smoke.mjs`：短暫建立、更新並關閉原生托盤；加上 `--notify` 會發送一則真實系統測試通知。

瀏覽器可用 `npm run demo` 驗證外觀、三個密碼欄位的眼睛按鈕、網域顯示切換（截斷／完整／隱藏）、天數設定、控制台更新／篩選／下載／清除與窄螢幕排版。展示模式所有改動僅在記憶體內，結束後不保留。

自動測試涵蓋排程、手動通知摘要、設定、日誌與本地端點；另已通過 Windows 服務重啟與托盤驗證，以及模擬頁面的瀏覽器操作驗證。這些測試未呼叫真實網域 API，也不等同於供應商真實續期已完成驗證。
