# 本地常駐使用指南

AutoUPDomain 以 Node.js 執行排程，透過原生系統托盤開啟預設瀏覽器中的 Web UI。Windows 與 Linux 可使用系統通知，也可另外啟用 Bark。

## 首次啟動

1. 安裝 Node.js 22 或更新版本。
2. 在專案目錄執行 `npm install`。
3. 設定專案根目錄的 `.env`，或啟動後在 Web UI 填入憑證。
4. 執行 `npm start`。Windows 也可雙擊 `Start-AutoUPDomain.vbs`，以隱藏終端視窗的方式啟動。

`.env` 範例：

```dotenv
API_KEY=你的API_KEY
API_SECRET=你的API_SECRET
BARK_API=none
```

`BARK_API=none` 表示不使用 Bark，仍可使用系統通知。需要 Bark 時改成自己的 HTTPS 推送網址；參考 [envExample](envExample)。現有 `.env` 不需要重新建立或覆蓋。

憑證齊全且排程未暫停時，服務會自動檢查。若只是試用介面，執行 `npm run demo`；展示模式使用模擬資料，不讀取真實 `.env`。

## 設定來源

同一設定欄位的優先序如下：

| 順序 | 來源 | 何時生效 |
| --- | --- | --- |
| 1 | Web UI 已儲存的設定與加密憑證 | 儲存後立即生效，重啟後保留 |
| 2 | 啟動程序的 `API_KEY`、`API_SECRET`、`BARK_API` 環境變數 | 啟動時 |
| 3 | 專案根目錄 `.env` | 啟動時 |
| 4 | 程式預設值 | 未提供相應設定時 |

修改 `.env` 後需重啟；若 Web UI 已儲存該欄位，應直接在面板更新。更改工作目錄不會改變常駐服務讀取的 `.env` 位置。

API Key、API Secret、Bark 網址預設遮蔽。眼睛按鈕只切換目前輸入的文字；已儲存憑證不會回傳到瀏覽器。欄位留白代表保留，儲存後會清空輸入並恢復遮蔽；離開分頁也會恢復遮蔽。

## 按天安排檢查

在「檢查間隔」輸入數字、選擇「天」或「小時」，再按「儲存設定」。

| 範例 | 效果 |
| --- | --- |
| `7` 天 | 每次成功檢查完成後，7 天後再次檢查 |
| `30` 天 | 每次成功檢查完成後，30 天後再次檢查 |
| `60` 天 | 每次成功檢查完成後，60 天後再次檢查 |
| `12` 小時 | 每次成功檢查完成後，12 小時後再次檢查 |

預設為 1 天。支援整數 1–90 天，或 1–2160 小時。天代表 24 小時的間隔，不是固定某個日曆日期或當地時間。

切換單位會換算表單數值；小時換成天時不足一天的部分向上取整，至少為 1 天。按儲存才生效。舊版小時設定載入時會保留原本間隔。

「少於幾天時續期」與檢查間隔不同：預設剩餘天數小於 170 天才會嘗試續期，門檻可設 1–180 天。續期成功後會重新查詢，確認到期時間確實延長。安排檢查間隔時應留足續期門檻內的處理時間，例如每 30 天檢查、少於 170 天續期。

### 排程如何恢復

- 成功檢查完成後，以完成時間加上間隔，計算下一次檢查。
- 修改間隔並儲存時，改以儲存時間起算。
- 檢查失敗時，1 小時後重試，不等待完整的天數間隔。
- 重啟或睡眠恢復後，若已錯過預定時間，30 秒內補跑一次。
- 暫停排程不影響「立即檢查」，手動與排程不會重複同時執行。
- 關閉瀏覽器不會停止服務；托盤「退出」會等待當前任務收尾。

電腦關機、使用者登出或服務已退出時不會執行檢查。

## 執行控制台

控制台每秒取得最新紀錄，顯示檢查開始、網域清單查詢、尚未達門檻的略過、續期確認、重試及通知結果。任務尚未完成時也會顯示進度。

| 控制項 | 行為 |
| --- | --- |
| 全部日誌／警告與錯誤／僅錯誤 | 篩選目前顯示內容 |
| 暫停更新 | 固定控制台畫面，背景任務仍繼續 |
| 繼續更新 | 取得最新可用紀錄 |
| 自動捲動至最新 | 有新紀錄時捲至最下方；取消後可閱讀前面的內容 |
| 下載日誌 | 下載控制台目前緩存的完整紀錄，不受畫面篩選影響 |

保留最近 200 筆。暫停畫面很久後恢復，較舊的紀錄可能已超過保留上限。這是近期排障紀錄，不是完整的長期稽核檔。

流程紀錄也會輸出到啟動終端；最近紀錄在任務完成、儲存設定和正常退出時寫入 `state.json`。強制終止可能失去尚未保存的最後幾筆。服務啟動與執行錯誤另外寫入 `service.log`。

## 通知與外觀

系統通知和 Bark 可各自開關，修改後需儲存。「測試已儲存的通知設定」使用已儲存值，不使用尚未儲存的表單內容。

平常查詢成功不通知；續期結果、檢查失敗及恢復時通知。相同的連續清單查詢錯誤只通知一次；續期未確認仍會逐輪提醒。通知工具接受請求不代表使用者一定看見通知，還會受系統勿擾與通知權限影響。

右上角「外觀」可選跟隨系統、淺色或深色。偏好保存在目前瀏覽器的網站資料中；更換瀏覽器或連接埠後可能需要重新選擇。

## 啟動方式與資料位置

| 指令／選項 | 用途 |
| --- | --- |
| `npm start` | 常駐服務、托盤與預設瀏覽器 |
| `npm run start:headless` | 無托盤服務，不自動開啟瀏覽器；終端印出面板連結 |
| `npm start -- --no-open` | 保留托盤，但不自動開啟瀏覽器 |
| `npm start -- --ignore-env` | 忽略 `.env` 與憑證環境變數；已儲存的設定仍有效 |
| `npm run main` | 單次 CLI，讀取目前工作目錄的 `.env`，完成後退出 |
| `npm run demo` | 模擬資料展示 |

常駐服務預設監聽 `127.0.0.1:17843`。從托盤開啟可取得目前有效的存取連結；重啟後舊連結的 token 會失效。

| 平台 | 預設資料目錄 |
| --- | --- |
| Windows | `%APPDATA%/AutoUPDomain` |
| Linux | `$XDG_CONFIG_HOME/AutoUPDomain`，未設定時為 `~/.config/AutoUPDomain` |

`AUTOUPDOMAIN_PORT` 和 `AUTOUPDOMAIN_DATA_DIR` 必須透過啟動程序的環境設定傳入，不是 `.env` 支援的設定欄位。連接埠 `0` 表示自動分配。使用自訂環境或無托盤模式時，面板不提供登入自啟動設定。

登入自啟動是使用者登入時啟動，不是開機前就運作的系統服務。移動專案或移除 Node.js 前，先停用自啟動，移動完成後再啟用。

更多平台需求與問題排查請看 [疑難排解](疑難排解.md)。
